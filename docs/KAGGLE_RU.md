# Запуск исследования доли просмотра в Kaggle

Основной файл: **KION_WatchFeedback_5methods_Kaggle.ipynb**. Он автономный: загружать другие файлы проекта не требуется. Полный план — пять методов × три seed × два временных среза, всего 30 обучений.

## Первый запуск

1. Создайте Kaggle Notebook и импортируйте этот `.ipynb` через импорт ноутбука.
2. В настройках включите **Internet** и **GPU**. T4 подходит; при двух T4 используется одна карта, cuda:0.
3. Поля `DATA_ARCHIVE` и `RESUME_FROM` оставьте пустыми. Научные параметры `CFG` менять не нужно.
4. Нажмите **Run All**. Сначала загрузится проверенный KION и подготовятся данные; затем короткий технический пилот напечатает ориентир времени всей серии. После этого начнётся полная очередь.
5. После сообщения «Исследование завершено: все 30 моделей оценены» скачайте **kion_watch_feedback_50k_S20_v1_results.zip** по ссылке в последней ячейке или из файлов `/kaggle/working`.

Ни Google Drive, ни прежние архивы первой статьи не нужны. Ноутбук использует установленный PyTorch; автоматически менять его версию он не будет.

## Что он проверяет

| Метод | Обработка просмотра |
| --- | --- |
| ALL | Равные веса всех допустимых взаимодействий |
| DELETE10 | Просмотры ≤10% удаляются из истории до обрезки |
| TARGET10 | Такие просмотры сохраняются в контексте, но имеют нулевой вес как цели |
| STEP10 | Вес 1 при ≤10%, иначе 3 |
| SOFT | Вес 0,2 + 0,8 × доля просмотра от 0 до 1 |

Для всех: компактная BERT4Rec, окно 20, маскирование 35%, 20 000 обновлений, seed 17/29/43. Разбиения по времени заданы внутри. Общими остаются каталог, когорта и будущие цели. На первом плане — NDCG@10 для доли просмотра ≥50%; также сохраняются метрики любого просмотра и Recall@10.

## Сохранение и продолжение

Веса и прогресс находятся в `/kaggle/working/kion_watch_feedback_50k_S20_v1/runs`. `last.pt` записывается каждые 1000 шагов; готовые модели имеют `completed.json` и не переобучаются. Лёгкий ZIP не содержит весов и **не подходит сам по себе для продолжения**.

Перед завершением сессии сохраните версию ноутбука **с выходными файлами Kaggle**. Для новой сессии добавьте эти выходы как Input. Совместимая папка внутри `/kaggle/input` ищется автоматически. При необходимости задайте `RESUME_FROM` явно — путь к папке, где находятся `watch_study_plan.json` и `runs`, а не путь к ZIP отчёта.

Если ядро той же сессии остановилось, снова выполните ячейки: совместимая серия продолжится. После аварийной остановки может повториться до 1000 последних незаписанных шагов. Произвольная остановка посреди обновления не выдаётся за завершённый checkpoint.

По умолчанию `MAX_RUNS_PER_SESSION = 0` выполняет всё оставшееся. Если нужен заранее ограниченный запуск, положительное число задаёт максимум новых моделей этой сессии; общий план из 30 не меняется. Тест рассчитывается только после завершения всей очереди. Архив промежуточного состояния доступен после ячейки обучения, но окончательные выводы требуют полного архива.

## Если сессия отличается от сохранённой

План фиксирует конфигурацию, код, данные, версии Python/PyTorch/NumPy/pandas и GPU. При несовпадении продолжение останавливается с объяснением. Сохраните напечатанное сообщение — для разбора достаточно текста; отключать проверку или объединять разные среды не нужно.

Пустые и короткие истории DELETE10 обрабатываются явно. Пользователи с ними остаются в оценке. Пропуски доли просмотра не приравниваются к нулю; строки KION остаются агрегатами по последней дате, а не отдельными сеансами.

## Что прислать после завершения

**Один итоговый ZIP** с сообщением о завершении всех 30 моделей. Он включает:

- планы, конфигурации, код, среды и контрольные суммы;
- данные выбора когорты и каталога, журналы всех запусков;
- таблицы по моделям и методам, качество двух задач, SD и время;
- пользовательские метрики и рекомендации с отображением внутренних ID;
- парные интервалы, кривые обучения и согласованные PNG/SVG.

Файлы `best.pt` и `last.pt` остаются в сохранённых выходах отдельно. Основные интервалы 98,75% относятся к четырём заранее заданным сравнениям; остальные 95%-интервалы описательные. SD seed не заменяется пользовательским bootstrap. Сам процент просмотра не объявляется оценкой удовлетворённости.

Локальные технические проверки используют маленькую CPU-выборку и несколько шагов; они не являются научным результатом и не заменяют запуск на GPU. Их отчёт — `notebook_validation.json`.
